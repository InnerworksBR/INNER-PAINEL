## Delivered

- Added `agent/Inner.Network.Agent/`, an independent .NET 8 Windows x64 service named `InnerNetworkAgent`. Its config refresh, SNMP collection and outbox sending loops run independently; transient API/token failures preserve collection using the cached configuration. A definitive enrolled-refresh rejection stops cached collection and requires relinking, as detailed in Round 2.
- Implemented a real SNMP client using `Lextm.SharpSnmpLib` 12.5.7. v2c and v3 GETs support SHA-1/SHA-256 authentication with `authNoPriv` or AES-128 `authPriv`. Requests honor cancellation and bounded timeouts; table walks cap returned rows. The tested library is the stable version reviewed for .NET 8, and its MIT attribution/license ships in `agent/THIRD-PARTY-NOTICES.txt`. The copied upstream loopback simulator test sources carry their own MIT license in `agent/Inner.Network.Agent.Tests/SnmpSimulator-LICENSE.txt`.
- Added CIDR expansion with overlap de-duplication and a fail-closed 4,096-IP budget, exclusion handling, no ICMP prerequisite, stable persisted device IDs, reboot/counter-reset-aware interface rates, and SQLite persistence for sequence, local identity, counters, cached state and a bounded 100 MB/1,000-batch outbox. 64-bit octet/error/discard counters are serialized as decimal strings.
- Added DPAPI LocalMachine storage for tokens, pairing/session secrets and the full cached config. Pairing saves the initial refresh token before submitting its hash. Token rotation persists the old/new pair and retries that same pair after a lost response, matching Task 1's retry-safe refresh contract.
- Added `agent/Inner.Network.Agent.Setup/`, a self-contained WinForms installer with an embedded service payload, UAC elevation, progress and a copyable service-issued pairing code. It installs/updates the automatic LocalSystem service, preserves ProgramData state, restricts data ACLs to SYSTEM and Administrators, and reports when it is waiting for Internet access. The ZIP traversal check and pairing-status parser have focused tests.
- Added `agent/build-network-agent.ps1` (HTTPS `-ApiBaseUrl` required), optional PowerShell launch/status helpers, and `agent/NETWORK-AGENT.md`. The API base is normalized to `/api` once. The main customer flow is the standalone GUI installer; no JSON editing, installed .NET runtime, or PowerShell execution is required for the install.

## Wire and local storage contracts

- Pairing request: `POST /api/agent/v1/pairings` with `machine_id`, `hostname`, `agent_version`, `os_version`, and `detected_networks`. Status is polled using `pairing_id` and private `device_secret`; the human code is only presented in the installer/status output.
- Completion persists the locally generated refresh token before `POST /api/agent/v1/pairings/complete` sends its SHA-256 hash. Refresh posts `{refresh_token: old, replacement_refresh_token: newPersistedRaw}` so an ambiguous/lost response can be retried with the identical pair.
- Config comes from `GET /api/agent/v1/network/config`; each network consumes optional `network_scope_id` in addition to `id`, `cidr`, `enabled`, `snmp_port`, `excluded_ips`, and `credential_ids`. Credentials are held only in the DPAPI-protected config cache and are not placed in batches.
- Metrics go to `POST /api/agent/v1/network/metrics` with idempotency key `<agent_id>-<sequence>`. Device results are `success`, `partial`, `timeout`, `auth_error`, or `protocol_error`. An unavailable target has null response time and no fabricated zero metric.
- Durable files live under `C:\ProgramData\InnerWorks\NetworkAgent`: SQLite database, DPAPI-encrypted secret files, and a small pairing-status JSON containing only state, user code/expiry/URL (not the device secret or tokens). Installer ACLs apply recursively.

## Round 1 review fixes

The round-1 review was applied without touching the concurrent Hyper-V installer/build edits or any backend/frontend files. The network service keeps discovery and known-device polling in independent worker loops. Discovery submits bounded waves of 15 probes while both paths share a 16-request semaphore, leaving capacity for known-device polls during broad scans. A loopback-only orchestration test holds a discovery probe pending and proves known-device polling and heartbeat requests complete before that probe is released. Discovery remains on `discovery_interval_seconds`; known-device polling continues at `collection_interval_seconds`.

Discovery only stores a target after an SNMP response. Previously known targets that time out remain in inventory and produce failure observations with `interfaces: []`; authentication and protocol errors retain their corresponding backend result codes. Reconciliation removes known targets after a network is disabled, its CIDR/exclusions change, or its credential binding is removed. Trusted engine ID/serial aliases preserve identity across an IP move only when the claim is unambiguous; duplicate claims cannot fall back to an unrelated IP alias. Optional sysContact and ENTITY-MIB values remain null when unavailable. Interface observations include ifType and use ifHighSpeed, HC 64-bit counters, standard-counter fallbacks, and discontinuity-aware rate baselines.

The worker now sends the existing `/api/agent/v1/heartbeat` payload periodically with created/acknowledged sequence, pending count/bytes, collection result, discovery state/count/time. Heartbeat and API failures stay isolated from cached collection. Pairing resumes status/completion after a lost completion response even when the locally persisted refresh token exists; refresh requests are single-flight across worker loops. The service does not log the human pairing code. Only a server response explicitly identifying a revoked/missing agent disables cached queries, and that state persists across service restart; a network outage or ordinary expired access token does not discard valid cached configuration. Incoming config is checked for canonical IPv4 CIDRs, total address budget, exclusions, overlaps, IDs, credential references/security fields, ports, and intervals before replacing the DPAPI cache.

Metric observations are split into monotonic per-batch sequences below 3,800,000 UTF-8 bytes (under the backend 4 MiB limit) and no more than 5,000 devices. A single observation that exceeds the safe limit fails the collection enqueue explicitly instead of being truncated or creating a permanently unprocessable outbox head. Outbox deletion now requires a response with `status` equal to `accepted` or `duplicate` and a matching `sequence`. A malformed, generic, or mismatched 2xx response leaves the batch queued.

Backend validation rejections with HTTP 400 or 413 move that batch out of the retry queue into a bounded local diagnostic table (100 rows; only sequence, status code, fixed reason code and timestamp, no metric payload). They do not advance the acknowledged sequence. Later batches continue sending; transient 429/5xx and expired-access responses stay retryable. The heartbeat reports the safe `metrics_rejected_400_413` error code and the worker log identifies the rejected sequence.

IPv4 parsing now requires four canonical decimal octets without leading zeroes or shorthand. This prevents the .NET shorthand/octal interpretation of a configured address such as `010.0.0.1` from probing a different address than the backend authorization parser means.

Red/green evidence: the first round-1 coordinator run exposed an identity fallback merge and a test that accidentally allowed discovery to mark the known target fresh before its poll; the identity logic and test setup were corrected and the concurrent scheduling test now passes. The first config-cache test was rejected because its test fixture used a non-UUID scope; correcting the fixture made the validation/preserve-last-good tests pass. The first concurrent refresh test blocked in a synchronous fake HTTP handler; switching that test handler to async exercised the actual single-flight path without a harness deadlock. A real production-serializer test emitted the checked-in sanitized fixture at `agent/Inner.Network.Agent.Tests/Fixtures/network-metrics-v1.json`, including success, partial, known timeout, interfaces, sys_contact and if_type.

## Round 2 review fixes

The probe now resolves a target with the SNMP engine ID and ENTITY-MIB serial number before it records interface counters, and returns that resolved UID through the coordinator. The coordinator reuses the probe UID rather than resolving the same observation again by IP. A loopback UDP simulator test runs the actual `SharpNetworkDeviceProbe` through `NetworkCollectionCoordinator.DiscoverAsync`, moves a configured `/32` from one documentation address to another, and verifies both the device UID and non-null interface rate history are preserved. The test maps only those logical addresses to its loopback simulator socket; it makes no LAN query. Reintroducing IP-only probe resolution produces a failing UID assertion.

Enrolled refresh responses with HTTP 401 now durably set `agent_authorization_lost`, clear unusable enrollment/rotation secrets, stop cached collection, discovery, sending and heartbeat, and expose `relink_required` in `pairing-status.json` and `network-agent-status.ps1`. Startup reconstructs that status from the protected marker. A new successful pairing clears the marker. The worker treats a refresh 401 as a confirmed need to relink, without claiming that every invalid token proves server-side revocation. The HTTP lifecycle tests use the backend's expired-access and invalid-refresh error bodies: an expired config access token followed by a refresh 401 disables cached queries across a reconstructed lifecycle object; a successful refresh continues normally; a refresh 503 preserves cached polling of a known target.

Configuration validation now requires UUID-shaped network and credential IDs, in addition to existing UUID scope validation. The sanitized success/partial/timeout fixture uses valid UUIDs for network IDs and was regenerated by the production C# serializer, including `sys_contact` and `if_type`; backend can consume it without edits.

Red/green evidence: UUID-shape tests first failed because the validator accepted string IDs. The actual SNMP IP-move test failed under a temporary IP-only probe-resolution mutation because the moved observation received a different UID; restoring trusted resolution made it pass with counter history attached. The auth lifecycle test initially failed to compile because its lifecycle implementation did not exist; after implementation, the realistic unauthorized and transient-failure assertions passed.
